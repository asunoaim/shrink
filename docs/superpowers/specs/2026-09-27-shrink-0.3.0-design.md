# shrink 0.3.0: settings page and design audit fixes

Status: approved in brainstorming on 2026-09-27, waiting for spec review.
Builds on the v1 spec (`2026-09-26-shrink-v1-design.md`) and the design audit (`DESIGN-IS-2026-09-27/`, local only, 16/30).

## 1. Goal

1. A settings page, so people stop answering the same questions on every clip (folder dialog, audio tracks, mode, size).
2. Fix what the audit found: keyboard/focus, jargon and overpromising copy, the ad-hoc visual system, contrast and the slow "Opening…" screen.

Success looks like this:
- Someone who picks "Next to the original recording" exports with zero dialogs.
- Every control can be reached with Tab and shows a focus ring.
- A first-time user can name every control without reading the hint line.
- No literal colors, spacing, font sizes or radii remain in components; all of them come from `theme.css`.
- A clip shows its video as soon as the quick probe finishes, before the thumbnails and keyframes are ready.

The screen layout (header → video → timeline → export dock) and the export flow (idle → exporting → done) stay as they are.

## 2. Settings

### 2.1 What can be set

| Setting | Options | Default |
|---|---|---|
| Save clips to | Ask every time / Next to the original recording / Always this folder (+ path, "Change…") | Ask every time |
| Copy clips to clipboard | on / off | on |
| Audio (when a clip opens) | First track / All tracks / Same as last time | First track |
| Export as (when a clip opens) | Original quality / Shrink to size | Original quality |
| Target size (when a clip opens) | number in MB, 1–1000 | 25, or the value 0.2.x remembered |

These are all *starting points*. The export bar still changes things for the current clip, and doing so never writes back to settings. There is one exception: "Same as last time" remembers the tracks used in the last export.

### 2.2 Page

- A gear button (⚙, labelled "Settings") sits in the header, left of "Open…". It is disabled while an export runs.
- The settings page replaces the editor view. The header shows "← Back" and the title "Settings".
- Back or Esc returns to the editor exactly as it was. The editor stays mounted (hidden), so the video, highlights, playhead and export-bar state survive. Playback pauses when settings opens.
- Every change saves immediately; there is no Save button.
- Layout follows the approved mockup (`.superpowers/brainstorm/.../settings-page.html`): three cards, "Save clips to", "Copy clips to clipboard" and "When a clip opens", each with a one-line explanation. The footer reads "shrink <version> · What's new · GitHub". "What's new" opens the GitHub release page for the running version.
- Picking "Always this folder" with no folder set opens the folder picker right away. Cancelling that picker leaves the previous choice selected.
- The empty screen (no clip open) also shows the gear.

### 2.3 Storage

- File: `settings.json` in the app config dir (`%APPDATA%\io.github.asunoaim.shrink\`), owned by Rust. It survives updates. Uninstalling keeps it unless the user ticks the uninstaller's "delete app data" box.
- A new Rust module `settings.rs` holds a `Settings` struct with serde defaults per field:
  - a missing file, a missing field or an unknown field → defaults for what's missing;
  - a corrupt file → all defaults, and the corrupt file is kept as `settings.json.bad` for debugging.
- Writes are atomic: write `settings.json.tmp`, then rename.
- Commands: `get_settings() -> Settings` and `set_settings(settings) -> ()`.
- Migration: on start, if localStorage still holds `shrink.targetMb`, that value becomes `targetMb` in settings and the localStorage key is removed. This happens once.

### 2.4 Behaviour

- **Save location** is resolved when Export is clicked, by a pure function `resolveOutDir(settings, clipPath)`:
  - Ask → folder dialog (as today; cancel = no export).
  - Next to original → the clip's folder.
  - Folder → the saved folder if it still exists (new command `folder_exists`). Otherwise the folder dialog opens with the title "Your save folder is missing. Save clips to…".
  - "Try again" reuses the folder of the run it retries, as today.
- **Clipboard:** `ExportRequest` gets `copyToClipboard: bool`. Rust copies only when it's true. The frontend's retry path copies only when the setting is on. "copied to clipboard" appears only when a copy really happened.
- **Audio on open:** a pure function `initialTracks(setting, lastAudio, trackCount)`:
  - First → `[0]`
  - All → every track
  - Same as last time → `lastAudio` filtered to tracks that exist, falling back to `[0]` if nothing is left
  - Always `[]` when the clip has no audio.
  
  `lastAudio` is saved when an export starts.
- **Mode and size on open:** every opened clip starts in the setting's mode and size. The existing clamp to the slider range still applies per clip.

## 3. Keyboard and focus (audit #8, #4)

- **Q** = previous highlight, **E** = next highlight. This replaces Tab/Shift+Tab. They jump to the highlight's start and select it, exactly like Tab did. They are allowed during export, as Tab was.
- Tab/Shift+Tab are no longer intercepted. They move between controls in document order.
- **Space** toggles playback, except when a button is focused *by keyboard* (`matches(":focus-visible")`); then Space presses that button. A button clicked with the mouse doesn't count, so clicking "Shrink to size" and then pressing Space still plays.
- Letter shortcuts (I, O, Q, E) are ignored while typing in a text or number input. The same goes for Delete/Backspace and the arrow keys.
- One focus style for every control: `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }`.
- ARIA:
  - mode buttons get `role="radio"` and `aria-checked` inside the `radiogroup`
  - audio chips get `aria-pressed`
  - the toast ✕ gets `aria-label="Dismiss"`
  - the gear gets `aria-label="Settings"`
  - the playhead gets `tabindex="0"`, `aria-valuemin`, `aria-valuemax`, `aria-valuenow` and `aria-valuetext` (e.g. "0:42.3"); arrow keys on it seek like the global arrows
- The hint line text becomes: "Drag on the timeline or press I O to mark a highlight · click it or press Q E to jump there · Space plays · ← → frame, Shift second · wheel skips · Del removes". The README key table changes to match.

Out of scope: moving or resizing highlights by keyboard.

## 4. Words (audit #4, #6)

| Where | Old | New |
|---|---|---|
| Mode buttons | Original / Shrink | Original quality / Shrink to size |
| Audio chip without a title | Track1 | Audio 1 |
| Original-mode note | Lossless and instant. Each clip starts at the keyframe before your mark. | Same quality as the recording. Clips can start up to a second early, the closest point where a cut stays lossless. |
| Timeline lead-in tooltip | Lossless clips start at the keyframe before your mark | Lossless cuts start at the closest point before your mark |
| Timeline lead-in label | starts 0:40.0 | starts 0:40, or starts 0:39.5 (tenths only when the time isn't a whole second) |
| Format notation | "1080p · 120" and "1080p · 120 fps" mixed | always "1080p · 120 fps" |
| Suggestion chip | 720p · 120 (clean) | 720p · 120 fps · looks clean |
| Chosen-format line | to fit 8 MB cleanly (always) | "cleanly" only when the pick is clean; otherwise "as close to 8 MB as it gets" |
| Done row sizes | 7.9 · 8.0 MB | 7.9 MB · 8.0 MB |
| README | "instantly", "best quality that fits", "updates itself" | "without re-encoding", "the best quality shrink can fit", "tells you when an update is out" |

**Errors in plain language:**
- Rust gets `EngineError::user_message()` with one plain sentence per variant, e.g.:
  - ToolNotFound → "ffmpeg is missing. Reinstalling shrink fixes this."
  - Probe → "This file doesn't look like a video shrink can read."
  - Io → "Couldn't write to that folder: <reason>."
  - Ffmpeg → "The encoder failed on this clip."
  - Cancelled → "Cancelled."
- Commands serialize errors as that sentence.
- `ClipOutcome::Failed` carries `error` (the sentence) and `detail` (the raw text).
- The done row shows "2 failed · <first sentence>" and a "Details" button. It expands the full list: clip number, sentence and raw detail, selectable so it can be copied into a bug report.

## 5. Look (audit #3, #9)

The palette stays. `theme.css` becomes the single source of truth:

- **Spacing:** `--s1: 4px; --s2: 8px; --s3: 12px; --s4: 16px; --s5: 24px; --s6: 32px`.
- **Type:** `--t-xs: 11px; --t-sm: 12px; --t-md: 13px; --t-lg: 15px; --t-xl: 20px; --t-2xl: 28px`. No half pixels.
- **Radius:** `--r-sm: 6px; --r-md: 10px; --r-pill: 999px`. The unused `--radius` is removed.
- **Colors:**
  - New: `--on-accent: #2b2622` (dark text on orange, 4.8:1), `--muted-hi: #bcae9f` (unselected labels on `--panel-2`, 5.3:1), `--on-warn`, `--warn-zone`, `--scrim`, `--shadow`.
  - Every literal color in components moves to a token. `app.html` keeps its one literal background (needed before CSS loads), with a comment.
- **Effects:** no glow shadows (Export button, logo dot, selection, pending marker). Only one plain drop shadow token remains, for floating things (toast, overlay). The backdrop blur goes.
- **Weights:**
  - Inter 400/500/600 only; `font-weight: 700/800` in the UI becomes 600.
  - Sora loads 800 only, for the wordmark, and anything that asked for Sora 700 uses 800.
- **Fonts:** only the Latin subsets (`@fontsource/inter/latin-400.css` etc.), about 690 KB smaller.
- **Motion:** `@media (prefers-reduced-motion: reduce)` turns transitions off.
- Buttons stay pill-shaped. The dock uses `--r-md`.
- The undefined `.prog` class is removed or defined.

Acceptance: a grep over `src/lib/components` and `src/routes` finds no `#hex`, `rgb(`, `rgba(` and no px values outside a small allowed list. That list covers fixed geometry: the playhead knob, the 26 px grab zone, thumbnail height and 1–2 px borders, each with a comment.

## 6. Opening clips progressively (audit #8)

Today `open_clip` runs the full probe (including a packet scan for keyframes) and the thumbnail strip before anything shows.

New flow:
1. **`open_clip(path)`**: a quick probe (format + streams, no packet scan) → returns `ClipView` with empty keyframes. It also returns `thumbs` if they're already cached. The video shows now.
2. **`clip_keyframes(path)`**: the packet scan, run in the background. It returns the keyframes and stores them in the state's clip, but only if that clip is still the open one.
3. **`clip_thumbs(path)`**: builds the thumbnail strip in the background and returns its path. The frontend ignores the result if another clip was opened since.
4. **Encoder detection** starts in a background thread at app launch, not on the first open.
5. **Export:** Original quality never plans without keyframes. If they're still loading, `start_export` computes them first, and the button shows "Preparing…" meanwhile. Shrink mode doesn't need them.
6. **UI while loading:**
   - The screen says "Opening <file name>…" until step 1 returns (usually well under a second).
   - The thumbnail strip shows a flat placeholder.
   - The lead-in markers appear once keyframes arrive.

Failures in steps 2 and 3 are quiet: no thumbnails, no lead-in marker. Export in Original quality then retries the keyframe scan, and if that fails it reports the plain error.

## 7. Testing

- **Rust:**
  - `settings.rs`: defaults, missing file, missing field, unknown field, corrupt file (→ defaults + `.bad`), roundtrip, atomic write.
  - `probe`: the quick probe has no keyframes, and `keyframes()` matches the old full probe on the fixtures.
  - `plan`/`runner`: the `copyToClipboard` flag; `user_message()` for every variant.
- **TypeScript (vitest):**
  - `resolveOutDir` (all three modes, missing folder)
  - `initialTracks` (all three modes, fewer tracks, no audio)
  - the localStorage migration
  - the key mapping (Q/E, Space with and without a keyboard-focused button, inputs ignored)
  - the format notation helper
  - the lead-in label rule
- **Checks:** `npm run check`, `cargo clippy`, all existing tests stay green, plus the literal-grep acceptance check from §5.
- **Live app (manual, on David's PC):**
  1. Each save location.
  2. Clipboard off.
  3. Each audio default.
  4. Settings survive a restart.
  5. Tab walks every control with a visible ring.
  6. Q/E jump between highlights.
  7. Space after a mouse click plays.
  8. A 1 h clip shows its video before the thumbnails.
  9. Exporting before keyframes arrive gives a correct lossless cut.

## 8. Release

- Branch `release/0.3.0`; version 0.3.0 in package.json, Cargo.toml and tauri.conf.json.
- Release notes `docs/releases/0.3.0.md`, following STYLE.md, shown to David before publishing.
- There is no flag and no old-design fallback: 0.3.0 replaces 0.2.1 through the normal update.
- 0.2.x users get: the folder dialog as before (the default is Ask), the clipboard on as before, their remembered size as the default, and Q/E instead of Tab. The release notes mention the key change up top.

## 9. Not in 0.3.0

Recent clips, size presets, combining highlights, vertical crop, batch, frame-exact lossless cuts, moving or resizing highlights by keyboard, light theme, the OBS audio-track setup.
