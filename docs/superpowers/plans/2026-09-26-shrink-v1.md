# shrink v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build shrink v1 as specified: a Tauri app to trim gameplay clips losslessly or shrink them to a target size.

**Architecture:** A Rust engine (`src-tauri/src/engine/`) runs ffprobe/ffmpeg and holds all logic. Pure planning code (size math, keyframe starts, naming, ffmpeg arguments) is separated from process-running code so it can be unit-tested. A Svelte 5 + TypeScript screen (`src/`) talks to the engine through a few Tauri commands plus progress events.

**Tech Stack:** Tauri 2.11, Svelte 5 / SvelteKit (static adapter), TypeScript, Rust 1.97, ffmpeg 9 (gyan full build during development), clipboard-win 5, thiserror 2.

**Spec:** `docs/superpowers/specs/2026-09-26-shrink-v1-design.md`

**Execution note (2026-09-26):** David asked Claude to start building straight away while he slept, so there was no plan-review gate. To keep his usage budget for the building itself, this plan gives interfaces, file responsibilities and exact test cases per task; the code lives in the commits. Pre-flight checks were done before writing it: the scaffold command works, `protocol-asset` + `asset_protocol_scope().allow_file` compile, a clipboard-win `raw::set_file_list` roundtrip passes, and the HEVC OBS clip decodes in Edge's engine (HEVCVideoExtension 2.5.33 installed).

## Global Constraints

- Windows only for v1. Tauri identifier `io.github.asunoaim.shrink`, product name `shrink`, license GPL-3.0-or-later.
- Shrink output: H.264 in .mp4, `+faststart`, AAC 160 kbps stereo.
- Size math: `video = (target_bytes × 8 ÷ duration − audio) × (1 − 0.03)`. Retry at most 2 times when over target; never deliver a file above the target.
- Warn below 0.035 bits per pixel per frame; count as clean at 0.045 or above.
- Encoder order: `h264_nvenc` → `h264_amf` → `h264_qsv` → `libx264`.
- Output name: `<stem> - clip N.<ext>`, with ` (2)`, ` (3)` … added when the name exists. Never overwrite.
- Original quality: stream copy in the source container; start at the keyframe at or before the section start.
- Colors and fonts: exactly as in spec §4 (Dusk tokens, Fraunces logo, Inter UI).
- ffmpeg is never spawned with a visible console window (`CREATE_NO_WINDOW`).

## Review Focus

1. **Paths with spaces, brackets, umlauts** (e.g. `Replay 2026-09-26 00-28-31.mp4`, `Clips (alt)\Ä.mp4`). Arguments are passed as a Vec to `Command`, never through a shell. Test: a fixture copied to a name with spaces and `ä` exports correctly.
2. **Sections touching the clip edges** (start 0, end = duration, end beyond duration). Clamp to [0, duration] and reject empty sections. Planner unit tests.
3. **Clip without audio / with 1 track / with 3 tracks.** Test: fixture without audio exports in both modes; audio selection out of range is rejected.
4. **Very long recordings (1 h+).** Probing must not decode the video: keyframes come from packet flags, thumbnails from `-skip_frame nokey`. Checked by construction, and timed manually on a long file when one is available.
5. **Cancel during a job.** The partial file is removed and the remaining jobs report Cancelled. Runner integration test.

## Phase 1: Engine (Rust, headless, fully tested)

### Task 1: Scaffold + HEVC preview spike
**Files:** the whole scaffold from `npm create tauri-app@latest shrink -- --template svelte-ts --manager npm --identifier io.github.asunoaim.shrink --yes`, copied into the repo root. Then:
- `src-tauri/Cargo.toml`: add the `protocol-asset` feature, thiserror, and clipboard-win (windows only); license GPL-3.0-or-later.
- `tauri.conf.json`: set `assetProtocol { enable: true, scope: [] }`, so files are allowed at runtime per opened clip.

**Spike:** a temporary page reads `SHRINK_SPIKE_CLIP`, allows that file in the asset scope, plays it, seeks to 30 s, and reports `{loaded, w, h, seeked}` to stdout via a command.
**Pass:** the OBS HEVC clip reports loaded + seeked. The result is recorded in this plan, then the spike code is removed.
**Result (2026-09-26):** PASS. The HEVC `hev1` 1080p120 OBS clip gave `{loaded, 1920×1080, seeked to 30 s}`; a 1440p60 H.264 MW3 clip gave `{loaded, 2560×1440, seeked}`. Direct playback is the main path, and the proxy stays a fallback.

### Task 2: Tool locator + test fixtures
- `engine/tools.rs`: `Tools { ffmpeg: PathBuf, ffprobe: PathBuf }`, `Tools::locate() -> Result<Tools, EngineError>`. Lookup order: `SHRINK_FFMPEG_DIR` → folder of the running exe → `PATH` → WinGet Gyan folder. `Tools::cmd(&self, Tool) -> Command` sets `CREATE_NO_WINDOW`.
- `engine/error.rs`: `EngineError { ToolNotFound, Probe, InvalidRequest, Ffmpeg{code, log}, Cancelled, Io }`, serialized as a string for the UI.
- `tests/common/mod.rs`: fixtures are generated once into `CARGO_TARGET_TMPDIR`. `fixture_two_tracks()` = 640×360, 60 fps, 10 s, x264 with a keyframe every 1 s (`-g 60 -keyint_min 60 -sc_threshold 0`), 2 AAC tracks titled Game/Mic. `fixture_no_audio()` is the same without audio.
- Tests: `locate()` finds both tools; the fixture exists and is > 0 bytes.

### Task 3: Clip reader
- `engine/probe.rs`: `probe(&Tools, &Path) -> Result<ClipInfo>`. `ClipInfo { path, format_name, container_ext, duration, size_bytes, bitrate, width, height, fps, video_codec, audio_tracks: Vec<AudioTrack{index, channels, title}>, keyframes: Vec<f64> }`.
- Keyframes come from `ffprobe -select_streams v:0 -show_entries packet=pts_time,flags -of csv=p=0` (packets only, no decoding).
- Tests on the fixtures:
  - duration ≈ 10, 640×360, 60 fps, codec h264
  - 2 tracks titled Game/Mic; 0 tracks on no-audio
  - keyframes ≈ [0,1,…,9]
  - a non-video file gives `EngineError::Probe`

### Task 4: Quality math (pure)
- `engine/quality.rs`: `AUDIO_BPS=160_000`, `SAFETY=0.03`, `WARN_BPP=0.035`, `CLEAN_BPP=0.045`.
- Functions:
  - `video_bitrate(target_bytes, duration, has_audio) -> u64`
  - `bpp(bitrate, &Format) -> f64`
  - `warn_zone_max_bytes(duration, has_audio, &Format) -> u64` (the size where bpp = WARN)
  - `slider_max_bytes(&ClipInfo, longest_section) -> u64`
  - `suggestions(target, duration, has_audio, &Format) -> Vec<Suggestion{format, bpp, clean, suggested}>`
- `Format { width, height, fps }`. Candidate ladder: heights 1440/1080/720/480/360, fps source/60/30, never above the source.
- Tests:
  - 25 MB / 30 s with audio → exact expected bitrate
  - bpp of 12 Mbps at 1080p120 ≈ 0.048
  - the zone boundary round-trips: bpp at `warn_zone_max_bytes` ≈ WARN
  - 10 MB / 30 s at 1440p120 → suggested = highest clean candidate (720p60), plus the next-higher alternative
  - a target large enough → no suggestions
  - nothing clean at all → lowest candidate flagged `suggested`, `clean=false`

### Task 5: Encoder
- `engine/encoder.rs`: `enum Encoder { Nvenc, Amf, Qsv, X264 }` (serde lowercase), `ORDER`, `ffmpeg_name()`, `is_hardware()`, `video_args(bitrate, gop: Option<u32>) -> Vec<String>`.
  - NVENC: `-preset p5 -tune hq -rc vbr -multipass fullres -spatial-aq 1 -temporal-aq 1 -rc-lookahead 32 -bf 3`
  - AMF: `-quality quality -rc vbr_peak`
  - QSV: `-preset slow`
  - x264: `-preset medium`
  - all: `-b:v X -maxrate 2X -bufsize 2X -profile:v high -pix_fmt yuv420p`
- `detect(&Tools) -> Encoder`: a 0.2 s 256×256 lavfi test encode per candidate; first success wins; `X264` if none.
- Tests: the args contain the bitrate for each encoder; `detect` returns an encoder that really encodes (run the probe encode again).

### Task 6: Planner + naming (pure)
- `engine/naming.rs`: `output_path(dir, stem, n, ext, exists: &dyn Fn(&Path)->bool) -> PathBuf`.
- `engine/plan.rs`:
  - `Section{start,end}`
  - `Mode::Original | Mode::Shrink{target_bytes, format: Option<Format>}`
  - `ExportRequest{sections, mode, audio_tracks: Vec<usize>, out_dir}`
  - `ExportJob{clip_number, input, output, start, duration, actual_start, audio_tracks, kind: JobKind}`
  - `JobKind::Copy | JobKind::Encode{encoder, video_bitrate, target_bytes: Option<u64>, scale: Option<Format>, gop: Option<u32>}`
  - `plan(&ClipInfo, &ExportRequest, Encoder, exists) -> Result<Vec<ExportJob>>`
  - `ExportJob::args() -> Vec<String>` (always `-nostdin -y -progress pipe:1 -nostats`)
  - `actual_start(keyframes, start) -> f64`
- Copy mode:
  - `-ss kf+0.001 -i in -t dur -map 0:v:0 -map 0:a:i… -c copy -avoid_negative_ts make_zero`, plus `-movflags +faststart` for mp4/mov
  - extension = source extension
- Encode mode:
  - `-ss start -i in -t dur`
  - a filter_complex for scale/fps and amix (for more than one track); `-c:a aac -b:a 160k -ac 2`, or `-an`
  - `.mp4` + faststart
- Tests:
  - clip numbers follow timeline order
  - clamping to [0, duration]; empty or inverted sections are rejected; no sections are rejected
  - actual_start picks the keyframe at or before the start (9.5 → 9, 3.0 → 3, 0.2 → 0)
  - naming collisions → ` (2)`
  - copy args keep the source extension and map the chosen tracks separately
  - 2 tracks in shrink → amix, 1 track → no amix, 0 → `-an`
  - a format override adds scale+fps
  - an audio index out of range is rejected
  - a target so small that the video bitrate is < 100 kbps is rejected

### Task 7: Runner
- `engine/runner.rs`:
  - `CancelFlag` (Arc<AtomicBool>)
  - `run_job(&Tools, &ExportJob, &CancelFlag, &mut dyn FnMut(f64)) -> Result<PathBuf>`: parses `out_time_us`, kills on cancel, deletes partial output on cancel or failure, and for Encode with a target, retries up to 2× at `bitrate × target/actual × 0.97` when the output is over target, then fails
  - `run_all(&Tools, &[ExportJob], &CancelFlag, &mut dyn FnMut(RunEvent)) -> Vec<ClipOutcome>`
  - `RunEvent::{ClipStarted{n,count}, Progress{n,fraction}, ClipFinished{n, outcome}}`
  - `ClipOutcome::{Done{output,size_bytes}, Failed{error}, Cancelled}`
- Integration tests on the fixture:
  - original export duration ≈ section from the keyframe, and its decoded frames match the source frames (framemd5 of the first 30 frames)
  - shrink to 300 KB → size ≤ 300 KB, H.264, 1 audio track
  - original with tracks [0,1] → 2 audio tracks
  - a cancel set during the job → Cancelled and no file left behind
  - progress callback values rise and end ≈ 1
  - an unwritable output dir → Failed, and the other jobs still run
  - a path with spaces + `ä` works

### Task 8: Preview helpers + clipboard
- `engine/preview.rs`:
  - `thumbnail_strip(&Tools, &ClipInfo, out_png, count, height)` using `-skip_frame nokey`, `fps=count/duration`, `scale=-2:h`, `tile=countx1`
  - `proxy_job(&ClipInfo, out, Encoder) -> ExportJob`: ≤720p, same fps, gop = fps/2, first audio track, 4 Mbps, no target
- `clipboard.rs`: `copy_files(&[PathBuf])` via `clipboard_win::raw::set_file_list`.
- Tests: the strip PNG has the width ≈ count × thumb width; the proxy runs, is ≤ 720p and plays (probe ok); a clipboard roundtrip.

## Phase 2: Screen (Svelte) + commands

### Task 9: Commands + events
- `src-tauri/src/commands.rs`:
  - `open_clip(path) -> ClipView`: probes, allows the asset scope, builds the thumbnail strip into the app cache, and returns info + strip path + encoder
  - `plan_info(...)` for slider max / zone / suggestions
  - `export(request) -> ()`: runs on a thread and emits `export://event`
  - `cancel_export()`
  - `make_proxy(path)`: emits progress, returns the proxy path
  - `copy_to_clipboard(paths)`
  - `initial_file()`: the CLI argument for "Open in shrink"
- Dialog + opener plugins: the folder picker and Show in folder.

### Task 10: Theme + shell + empty state
Dusk tokens as CSS variables, fonts (Fraunces + Inter bundled locally via @fontsource so the app works offline), title bar, drop zone, Open file…, drag-drop via `getCurrentWebview().onDragDropEvent`, error message for unreadable clips.

### Task 11: Preview player
`<video>` on the asset URL. On `error` it calls `make_proxy` and swaps the source. Keys: Space; ←/→ step by 1/fps; Shift+←/→ step by 1 s. A time readout.

### Task 12: Timeline
The thumbnail strip, playhead click/drag to seek, drag-to-draw sections, I/O keys, edge and body dragging, select + Delete, number badges in time order, and an "actual start" marker in Original mode.

### Task 13: Export bar
Original/Shrink toggle, the size slider (1 MB…max, remembers the last value in localStorage, click to type), the yellow zone, the inline warning line with one-click fixes, audio checkboxes per track (label = track title or "Track N"; only shown when there are ≥ 2 tracks), and the Export button.

### Task 14: Export flow
Folder picker → export → progress line with Cancel → done row (sizes, clipboard note, Show in folder, Done) or failed clips with Try again.
